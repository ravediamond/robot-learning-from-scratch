# Model answers

1. Typical: MSE head lower val MSE, flow head ~0.9+ success vs ~0.5; paired n01 (flow only) ≈ 80–100, n10 ≈ 0–5; McNemar p ≪ 0.001. Ship the flow head.
2. MSE is minimized by the conditional mean, which is exactly what the MSE head predicts; a sampler picks one mode and is "far" from the average demo even when correct. Val MSE is still useful for: overfitting checks, catching bugs (normalisation, loading), comparing checkpoints of the SAME model class, and as a cheap filter; not for ranking different action-head families.
3. Steps to success, collision/failure type and time, min distance to obstacles, action smoothness (jerk), chunk boundaries, inference latency, the seed and start state, the checkpoint hash, and a video/trajectory. Your register needed exactly these to read failures and to re-derive numbers.
4. Different random starts per call: each policy faces different difficulties; with n = 100 the start-to-start variance can swing success by several points, enough to flip a small gap. More trials shrink the noise slowly (√n); pairing removes it at the source. Fix = fixed, shared starts (plus more trials if the gap is small).
5. Marked object positions on the table, photos of the layout, scripted resets, the same arm start pose. Pairing breaks with imprecise placement, lighting changes, servo heating/drift over a session, operator interventions: interleave policies (ABAB) and log the actual layout.
6. A funnel: offline filters (val loss within a band, action-distribution checks, open-loop replay error on held-out episodes, sim success if a sim exists) to drop clearly bad checkpoints; then a small paired robot screen (e.g. 10 fixed starts) for the top few; then a full pre-registered eval (30–50 paired trials) for the best one or two. Decide the rule before seeing the numbers.
