# Model answers

1. `pred = model(x)`; `loss = loss_fn(pred, y)`; `opt.zero_grad()` (missing → grads accumulate, D3 review); `loss.backward()` (missing → no grads, weights never move; placed before zero_grad → you erase what you computed); `opt.step()` (missing → nothing updates; placed before backward → updates with last step's grads). Plus `model.train()` before, `eval()`+`no_grad()` for validation.
2. Proves the model + loss + optimizer wiring can fit data: shapes, loss sign, gradient flow, lr range. Does NOT prove generalization, correct data pipeline for the full set, or that labels are right (it can memorize wrong labels). Fails → bug in code (detached tensor, wrong loss, lr far off, frozen params). Passes but val bad → data (leakage, distribution shift, too little data) or regularization/capacity.
3. `eval()` switches layer behavior (Dropout off, BatchNorm uses running stats instead of batch stats). `no_grad()` stops graph recording. Independent; eval usually needs both. Other layers: BatchNorm, and any custom module checking `self.training` (e.g. stochastic depth, noise injection, some VAE samplers).
4. At inference the batch is 1 frame: BN must use running stats estimated during training; if those are off (different lighting, correlated batches of frames from one episode), the shift is large. Batches of correlated frames give biased batch stats during training too. LayerNorm/GroupNorm do not depend on the batch, so they behave the same at train and test.
5. Expected ln(10) ≈ 2.30. 4.7 means confident wrong logits at init: logits too large (bad init scale, a missing normalization of inputs, a huge bias), or labels mismatched with outputs (e.g. one-hot passed where indices expected, or targets offset). Check logit std at init.
6. Adam keeps two running averages per parameter: of the gradient (m) and of the squared gradient (v); the step is m/√v, so each parameter's step is normalized to roughly lr regardless of gradient scale. SGD's step is lr × gradient, so its good lr depends on gradient magnitude. That is why Adam's lr is typically 1e-4 to 1e-3 and SGD's 1e-2 to 1e-1.
7. Not a bug (add_module registers each layer), just non-idiomatic: use `nn.ModuleList`. With a plain list and no `add_module`: the layers are not in `parameters()` (optimizer never updates them), not in `state_dict()` (not saved: a reloaded model has random weights), not moved by `.to(device)`. You notice via `count_params`, or a saved checkpoint that is suspiciously small, or a device mismatch error.
8. (a) Episode leakage reversed: val episodes are a different operator/day/lighting → check per-episode val loss vs metadata. (b) Overfitting on few demos (50 episodes is small): the policy memorizes trajectories → check train/val gap vs number of episodes, add augmentation. (c) Val loss is not the metric: BC val MSE can rise while success rate stays the same or improves (multimodality: averaging modes vs committing). Check success rate on the robot for 2 checkpoints before trusting val loss.
