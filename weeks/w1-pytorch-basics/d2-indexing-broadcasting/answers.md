# Model answers

1. Align shapes from the right; each pair of dims must be equal or one of them 1; missing dims count as 1. Silent case: `pred (B,)` minus `target (B, 1)` gives `(B, B)`; the loss is then the mean over all pairs, it trains, and it is wrong. Always assert shapes before a loss.
2. Padded entries count in the denominator, so samples with padding get a smaller loss and a smaller gradient. Padding happens on chunks that run past the end of the episode, i.e. the last H steps: the grasp/place/release. The policy is weakest exactly where tasks fail. On the robot: hesitation or sloppy release at the end, while the approach looks fine.
3. (N, M, D) floats: 100k × 100k × D × 4 bytes, i.e. 40 GB per dim of D. Chunk over N (loop over blocks of 1k rows; a loop over blocks is fine). The expansion `||a||² + ||b||² − 2 a·bᵀ` uses one matmul (N, M), no (N, M, D) tensor; risk: catastrophic cancellation gives small negative values for near-identical points, so clamp at 0.
4. (a) The scorer is exploited: the argmax picks the candidate where the scorer is most wrong (optimizer's curse / Goodhart). (b) The candidates do not differ in the way that matters (low diversity: all N chunks fail the same way), so ranking cannot help. Also: scorer judges a chunk out of context (open-loop), while the failure comes later.
5. `x[arange(B), idx]` covers picking one element per row. `gather` is needed when index has more than one entry per row or more dims, e.g. pick K tokens per row from (B, T, D): `gather(1, idx[..., None].expand(-1, -1, D))`. It is also the standard in log-prob code.
6. Autograd saves some tensors for the backward pass. If you modify one in place, the saved value is no longer the one used in the forward; PyTorch detects it with a version counter and raises "one of the variables needed for gradient computation has been modified by an inplace operation".
