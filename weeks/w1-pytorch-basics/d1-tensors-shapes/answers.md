# Model answers (short; yours should be about this long)

1. `view` reinterprets the same memory with a new shape; it needs the strides to be compatible (contiguous, roughly). After `transpose`, memory order no longer matches row-major order, so `view` raises. `reshape` returns a view when it can and copies when it must. Contiguous = elements laid out in memory in the order a row-major traversal visits them.
2. Stride = how many elements to jump in memory to move by one along each dim. `unfold` builds a new shape/stride over the same storage, so windows overlap in memory: zero copy. On 1M frames with H=50, a copy would be 50× the dataset in RAM.
3. fp32: 8 exponent bits, 23 mantissa. fp16: 5/10, small range, overflows and underflows (needs loss scaling). bf16: 8/7, same range as fp32, less precision, no loss scaling needed. Optimizer state (Adam moments, master weights) stays fp32 because tiny updates vanish in 7-bit mantissa (predict item 10).
4. It crashes later (e.g. `(x - mean)` with x (N, D) and mean (N,)) whenever N ≠ D and the broadcast fails; or silently broadcasts wrong when N == D. Non-crashing bugs give plausible but wrong numbers: training "works" with a worse result, and you blame the method instead of the code.
5. Pad to max: simple, wastes compute (mostly padding), needs masks everywhere. Bucketing: less waste, more code, batches differ in length. Fixed windows: what most policies do (they only need `obs_t` and `a_{t:t+H}`), constant memory, but you must handle the episode end (pad the tail chunk + mask).
6. Without eps: divide by 0 → inf/nan → policy outputs nan → arm command invalid. With eps: values become (x − mean)/1e-8: any tiny change at inference explodes. Better fix: clamp std to a minimum (e.g. 1e-2 in joint units) or skip normalizing constant dims, and flag it: a constant gripper in training means the data never shows a grasp.
7. (a) Temporal consistency: one forward pass commits to a smooth sequence instead of re-deciding every step (less jitter, fewer mode switches). (b) Latency/compute: one inference per H steps, so a slow model can still run at control rate. Also: multimodal behavior is chosen once per chunk rather than flickering between modes.
