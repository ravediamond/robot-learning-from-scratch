# Model answers

1. Each head computes its own attention pattern, so the layer can attend to several things at once (one head tracks the gripper, another the target object, another the previous action token) instead of averaging them in one softmax. Same parameters because the D-dim projections are just split. In an action expert: heads attending to different cameras, to the instruction tokens, to nearby action steps (smoothness).
2. 4 linear layers D×D + biases: 4D² + 4D. Splitting into heads only reshapes; it adds no parameters. (D=64 → 16,640, both for 1 and 8 heads.)
3. With T time steps and h heads, the memory block of head i holds features from time steps i·T/h ... (i+1)·T/h, all dims mixed. Each "head" attends over a scrambled sequence. Still a fixed linear rearrangement followed by learnable projections, so the model can partly compensate, but attention patterns no longer correspond to time steps: worse.
4. The context (keys/values) length: projections are per-token, and attention normalizes over keys of any length; e.g. more image tokens or a longer instruction work mechanically (quality depends on training distribution and position encodings). The query length too (number of action tokens) mechanically, but a model trained on H = 50 actions has learned per-position behavior.
5. MQA shares one K/V head across all query heads; GQA shares K/V within groups. The KV cache shrinks by h (or h/groups) and memory bandwidth per generated token drops: faster decoding on memory-bound hardware like a Jetson. Small quality cost.
6. Depends on dtype and magnitudes. In fp32 with small values, 1e-3 suggests a real difference (e.g. missing bias, scaling by √D instead of √Dh, softmax over the wrong dim on a nearly symmetric input). In fp16/bf16 or with TF32 matmuls enabled, 1e-3 relative error can be normal. Check: rerun in float64; if the gap stays, it is a bug.
