# Model answers

1. Normalizing makes the similarity a cosine: it depends only on direction, the encoders cannot game the loss with norms, and similarities are comparable across batches. Cosines are in [−1, 1], too flat for a sharp softmax, so a learned temperature/scale (clamped, e.g. ≤ 100) sets how peaked the distribution is.
2. More negatives per positive: the task is harder and more informative (closer to the true contrastive objective), so representations improve. CLIP's softmax needs the whole batch's similarity matrix (all-gather across GPUs). SigLIP's per-pair sigmoid needs no batch normalization, works with smaller batches, and is cheaper to distribute.
3. Duplicates are treated as negatives, so the model is pushed to separate images that should match the same text: it learns spurious within-caption differences, and the loss cannot reach 0. Fixes: deduplicate captions within a batch, use multi-positive targets (soft labels over all matching captions), or SigLIP with labels +1 for all matching pairs. On teleop data (many frames, one instruction), use one frame per episode per batch, or multi-positive losses.
4. A new colour has no token embedding and the image tower never learned its channel pattern: accuracy collapses. "Zero-shot" means no task-specific training, but it only works within what the pretraining covered; claims should state the distribution.
5. Make embeddings huge for confident pairs to drive their loss to ~0, or shrink them to flatten everything; the loss then measures norm games rather than alignment, gradients become unstable, and the effective temperature varies per sample.
6. Possibly: as a progress/success detector (frame vs "bowl inside bowl"), for retrieval of similar episodes for data curation, or to check language grounding. But the data has few distinct instructions and many correlated frames (false negatives everywhere); pretrained SigLIP features + a small probe is usually the better first move.
