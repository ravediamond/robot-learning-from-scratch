# Model answers

1. Effective batch × 8 (if per-GPU batch is kept). Options: keep the global batch (shrink per-GPU) to keep hyperparameters; or scale lr (linear scaling for SGD, roughly sqrt for Adam) with a longer warmup; re-tune if needed. Also: steps per epoch ÷ 8, schedules defined in steps must be adjusted.
2. Collectives (all-reduce in backward, barriers, broadcast of buffers) are matched by order across ranks; if one rank does an extra collective, the others wait forever. Classic: rank 0 runs evaluation through the DDP-wrapped model in train mode (forward syncs buffers / backward-free but buffer broadcast) or calls `dist.barrier()` inside an `if rank == 0` block. Evaluate with `model.module` under no_grad, or on all ranks.
3. BN statistics are per-GPU (small per-GPU batches → noisy stats, mismatched running stats). Fixes: SyncBatchNorm (synchronises stats, costs communication) or replace with GroupNorm/LayerNorm.
4. Model weights, optimizer state (moments), scheduler state, global step/epoch, RNG states (torch CPU/CUDA, numpy, Python, sampler generator), data loader position (epoch + index), gradient scaler (AMP), EMA weights if any. Most forgotten: optimizer state and RNG/data position.
5. Adam restarts with zero first/second moments: bias correction makes the first updates ~lr-sized in every coordinate regardless of gradient history, kicking the weights. With a scheduler not restored, the lr may jump back to its warmup/peak value. Recovery takes ~1/(1−β2) ≈ 1000 steps for v to re-average.
6. Communication (all-reduce of 450M grads per step: bandwidth-bound without NVLink; overlap with backward via buckets), data loading/decoding not scaling (CPU-bound video decoding), small per-GPU batch (lower utilisation), stragglers/imbalanced sequence lengths, rank-0 logging/eval/checkpointing pauses. Measure: profiler timeline per step (compute vs NCCL vs dataloader wait), GPU utilisation, step time vs per-GPU batch.
