# Model answers

1. λ = 0: z std ~0, prediction loss ~0: the encoder maps everything to one point, which the predictor trivially predicts. λ = 0.1: z std ~1, prediction error ~0.1 of copy-last, MLP probe ~0.99, linear ~0.3. λ = 1.0: similar or slightly worse prediction (the regulariser competes with the prediction loss). Collapse: the trivial constant embedding makes prediction free. Fix: SIGReg forces the batch of embeddings to be isotropic Gaussian, so they cannot all be equal.
2. Most of the next latent is the current latent (frames change a little per step): learning a correction is easier than learning the full map, and at initialisation the predictor equals copy-last exactly, so any learning shows up as beating that baseline. It also stabilises long rollouts.
3. Information is present (MLP ~0.99) but encoded nonlinearly (linear ~0.3): the latent is "folded"; L2 distances in latent are a poor proxy for distances in the world, so planning by latent distance to a goal will struggle (you'll measure it tomorrow).
4. Your register ran copy-last style baselines, probes (C1 probe, G1 probes), the checkpoint-load audit and surprise/receptive-field analyses. Add: linear vs MLP probes on held-out episodes, the effective rank/spectrum, and the latent-distance vs world-distance correlation before any planning claim.
5. It learns the identity map; with targets equal to inputs the loss is near zero from the start (the residual predictor starts as identity!). Copy-last error equals its error by construction.
6. Architecture: a ViT/CNN encoder from pixels (~15M params total), an action-conditioned predictor (transformer) autoregressively predicting the next embedding. Losses: next-embedding MSE + SIGReg (isotropic Gaussian regulariser via random projections and Epps–Pulley), one hyperparameter, no EMA/stop-grad/pretrained encoder. Good at: stable end-to-end training on one GPU, fast planning (up to 48× faster than DINO-WM), physically meaningful latents (probes), surprise on implausible events. Fails / open: long-horizon planning with latent-distance costs, tasks needing fine contact detail, evaluating policy rollouts when trained on clean demos (your register).
