# Model answers

1. Each test at α has an α chance of a false positive when the null is true; with m tests the chance that at least one fires is about 1 − (1 − α)^m (26% for 6 tests). Bonferroni tests each at α/m: simple, conservative. Holm is uniformly more powerful with the same family-wise guarantee: use it for a handful of planned comparisons where any false claim is costly. FDR (Benjamini–Hochberg) controls the expected share of false discoveries among the claims: right for screening many conditions (dozens of tasks or ablations) where a few false leads are acceptable.
2. The uncertainty of the conclusion people actually draw ("which is best"), accounting for the correlation between policies on shared starts. Overlapping CIs do not mean "no difference" and separated CIs are a crude test; P(best) = 0.55 vs 0.40 says plainly that the winner is not settled.
3. About 27 points (unpaired normal approximation, 80% power, α = 0.05). Say it before the results, design the comparison so that the effects you care about are that big (or pool sessions to raise n), treat smaller observed gaps as "not resolved", and use the number to argue for more robot time or for a cheaper proxy evaluation.
4. Pairing helps when start configurations matter a lot (some easy, some hard for every policy): shared difficulty cancels and only discordant starts carry information, so the test is sharper. It does not help when outcomes are nearly independent of the start (all variance is within-start randomness), and it cannot fix too few discordant pairs.
5. Optional stopping: each look is another chance to cross 0.05 by luck, so the real false-positive rate rises far above 5% (with many looks it approaches 1 under the null). Correct: fix n in advance and look once; or use a sequential design with an alpha-spending boundary (O'Brien–Fleming, Pocock) or always-valid sequential tests (e-values, mixture SPRT) that permit continuous monitoring.
6. Seeds add a second variance source (training randomness) that rollouts on one checkpoint cannot see. Report per-seed success, analyse with seed as a random effect (or average per seed, then compare across seeds with the seed as the unit), keep the same start list for every checkpoint so pairing still works within seed, and budget: 5 seeds × 20 rollouts often tells you more about the method than 1 seed × 100.
