# Questions (out loud)

1. Name four sources of drift in a real-robot session and the protocol rule that neutralises each.
2. Why fixed start configurations, and how many? What is lost if they are too few?
3. What exactly does blinding protect against when a human labels success? How do you blind when the policies look different (one is jerky)?
4. Why validate records when they are written rather than at analysis time?
5. You have 3 hours of robot time and 4 policies. Plan the session: starts, repeats, resets, breaks.
6. An interviewer says "your 50 rollouts per policy are on one table, one lighting, one object set: so what?" Answer.
